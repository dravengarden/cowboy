# Columbus delivery procedure

Design example; not installed or activated.

Read the registered Columbus source's `AGENTS.md` and resolve the target project
identity. Native runtimes own the task; the workspace only routes to the owning
repository, checks and machine contracts.

For completed changes owned by Columbus, follow its current quality gate, fresh
Git integration and main publication policy without asking again for the
standing authorized step.

External projects keep their own commit/push rules. A Columbus authorization
cannot authorize their publication. Resolve their nearest guidance and a
project-specific procedure before any automatic external-project delivery.

Machine deployment is a separate scope and uses the owning machine's exact
commit/artifact and activation contract. An ordinary code or documentation task
does not imply a host deployment. Preserve active revisions, task isolation and
the runtime-only host boundary.

Require receipts for the intended milestone. Report missing authority or unknown
external outcome as such; do not treat native turn completion as publication or
activation evidence.
