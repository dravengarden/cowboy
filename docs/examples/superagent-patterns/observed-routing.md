# 历史模式集的共同执行约束

这是候选库的固定 guidance，不授予权限，不是新的任务执行器。

## 选择与派发

在已有 turn.completed 评估中先确认 session 参与模式、当前人类任务范围、
当前项目 procedure、worker 所有权和可读范围。observe 只输出观察，
coordinate 才可能按现有准入派发。当前实现要求同 owner、同执行 Machine
的已参与普通 live worker；暂停、Trash、托管子会话等排除条件仍生效。
不可用能力报告为缺口，不通过 shell、其他 MCP 或隐藏 agent 绕开。

优先处理阻止下一步的具体原因：失败恢复、审查发现、明确依赖；
其次处理剩余范围、交付证据、审阅材料和临时资源。通用 follow-through
是兜底，同一缺口不再另派一条。将一次任务的相关缺口合成一次具体 follow-up。
所有 pattern 共享原人类任务的因果预算（当前默认 2 次），没有各自的重试额度。
有效授权、状态和 pattern 版本在派发前重查。

未知派发或外部效果只查询原 operation，不生成新 ID 重放。
等待中的调用依靠已有完成事件；没有 cron、周期扫描、自唤醒或忙轮询。
预算耗尽、无进展或存在新决策时停止自动跟进，并报告具体阻塞。
历史“继续”和历史部署偏好只是识别线索，不是当前执行授权。

## Context 和 token

固定前缀保留版本化 guidance 与精简 pattern 索引，按需读取匹配规则正文。
动态末尾只放当前任务范围、变化的证据引用、缺口和本次预期动作；
不要反复贴完整 transcript、全部 pattern 或项目文档。每次只读取解决分歧
所需的分页片段；Cowboy 读取每页最多 4000 字符。

由原生 session 保存执行状态；使用现有回执与原生任务引用恢复，
不另建任务数据库或把实时状态写入 Markdown。稳定前缀有助于缓存，
但压缩、Provider TTL 和恢复后的真实 prompt 都可能影响命中，
不能承诺无 cache miss 或固定节省比例。先测真实 input/cache token
与每个有效干预的成本，再决定模型驻留和压缩策略。

## 从案例提炼下一版

协调者仅通过现有 learning 提案机制提出候选，不自动采用、修改权限或扩范围。
每个候选记录：明确触发、最小证据、一次监督动作、停止条件、反例、
适用项目、支持与失败案例的受控引用。一个案例只能算候选；
跨任务重复出现且反例边界清楚，才考虑提升为 global。
公司业务细节和原始 transcript 不进入共享库。

维护者审核后修改源 Markdown、提高 revision、重新导入新版本。
沿用现有每个人类任务的提案限额，不因多个 pattern 匹配重复提案。
后续通过原生记录区分：正确干预、误触发、重复催促、真实授权阻塞、
节省的人类提醒与实际 token 成本；这些是待收集指标，不是本次已经测得的效果。
