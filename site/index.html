The plugin ecosystem

Plugins are not add-ons.
They are the product boundary.

Every integration is independently versioned, packaged, signed, published, installed, upgraded, rolled back, and removed through one generic lifecycle. Cowboy learns capabilities from typed contracts instead of hardcoding vendor-shaped screens.

Exact from source to session

One lifecycle. No moving targets.

The thing a developer builds is the thing the Catalog verifies, the Machine installs, and the session runs. Exact identities survive the entire trip.

  1. 01
    Build

    A typed manifest and payload become one data-only .cowboy-plugin.

  2. 02
    Sign

    Publisher identity, contract fingerprint, and every runtime artifact are bound.

  3. 03
    Publish

    The Catalog exposes immutable releases without silently installing them.

  4. 04
    Install

    A chosen Machine activates a complete generation atomically.

  5. 05
    Run

    Sessions stay pinned to the exact installed release until an explicit change.

Typed capabilities

Let plugins describe themselves.

Provider marks, setup, authentication, model controls, activity, transcript style, and host behavior all travel through validated data contracts.

Shared components

Reuse implementation, keep releases independent.

Plugins pin exact SDK, UI, runtime, and code-intelligence components. A component can evolve without turning the whole ecosystem into one monolith.

Machine isolation

Install where the work actually runs.

The Hub joins Catalog releases with each Machine's platform and contracts. Credentials and runtime state stay at the owning boundary.

A live workspace, not a remote terminal

The browser can leave.
The work keeps moving.

Cowboy's Hub coordinates durable sessions while detached workers stay beside their worktrees on each Machine. Reconnect from another surface without moving the running agent.

Open source and ready to build

Put every agent within reach.

Cowboy is developed in a pinned Nix shell and runs with an in-memory, SQLite, or PostgreSQL store. Start locally, then enroll the Machines where your real work lives.

cowboy — quick start 
$ git clone https://github.com/dravengarden/cowboy.git
$ cd cowboy
$ nix develop
$ just build
$ ./target/release/cowboy serve \
    --database-url sqlite:///tmp/cowboy.sqlite3
